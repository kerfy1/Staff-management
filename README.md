# Telegram-бот управління персоналом (AI-агент на Haiku через OpenRouter) **Макет**

Кнопок немає — працівник і керівник спілкуються з AI-агентом звичайною мовою.
Агент має **окремий системний промпт і окремий набір інструментів під кожну функцію**
(роутер намірів → домен → промпт + tools).

## Швидкий старт

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # вписати BOT_TOKEN, OPENROUTER_API_KEY, MANAGER_IDS
python main.py
```

`MANAGER_IDS` — Telegram ID керівників через кому (свій ID: @userinfobot).
Хто в цьому списку — автоматично отримує роль керівника.

## Структура

```
config.py            налаштування з .env (ставки, коефіцієнти, модель)
db.py                SQLite: users, groups, shifts, requests, notes,
                     absences, cover_offers, reminders, history
ai/client.py         OpenRouter через OpenAI SDK (base_url = openrouter.ai/api/v1)
ai/prompts.py        ROUTER + окремий промпт на КОЖНУ функцію
ai/tools.py          інструменти (function calling), прив'язані до домену і ролі
ai/agent.py          роутер намірів + цикл tool-calling
services/dates.py    українські дати: "липень", "завтра", "5 серпня", "з 10 по 14"
services/payroll.py  розрахунок ЗП
services/reports.py  Excel: звіт + бланк під перевірку (з формулами)
services/staffing.py підбір заміни за найменшою кількістю годин
handlers/menus.py    меню працівника і меню керівника
main.py              aiogram + фоновий цикл нагадувань
```

## Як працює агент

1. **Роутер** (`prompts.ROUTER`) класифікує повідомлення в домен:
   - працівник: `attendance`, `requests`, `notes`, `payroll`, `reminders`
   - керівник: `staff`, `approvals`, `schedule`, `reports`, `comms`, `reminders`
2. Під домен підставляється **свій системний промпт** і **тільки свої інструменти**.
   Модель не бачить зайвих функцій → менше галюцинацій, дешевші запити.
3. Незареєстрований користувач жорстко замикається на домен `registration`.

## Реєстрація і групи

- Новий юзер пише `/start` → агент просить ПІБ + посаду → `register_employee`.
- Керівнику автоматично летить: «Новий працівник X. В яку групу розподілити?»
- Керівник відповідає «додай Кравця в групу Підтримка» → `assign_to_group`
  (група створиться, якщо її ще нема). «створити групу Підтримка» → `create_group`.

## Пошук по частині імені

`db.search_users()`: підрядок → початок слова → нечітке зіставлення (difflib).
«Кравець» знаходить «Кравець Василь». Якщо збігів кілька — агент перепитує.

## Підбір заміни (те, що просилось)

Керівник: *«Кравець Василь завтра не виходить на роботу»*
→ `mark_absence` → агент питає, чи шукати заміну
→ `find_replacement`: бере групу відсутнього, відкидає тих, хто вже має зміну /
вихідний / лікарняний, сортує за **найменшою кількістю годин у поточному місяці**,
**сам пише кандидату в Telegram** пропозицію. Працівник відповідає «так, можу» →
`answer_cover_offer` → підміна записується як додаткова зміна, керівнику йде сповіщення.

## Звіти (файлами)

- «звіт за липень» → `zvit_YYYY-MM-DD_YYYY-MM-DD.xlsx`
  аркуші: Зведення / Зміни / Заявки / Відсутності.
- «бланк зарплати за липень» → `blank_zp_*.xlsx` — **бланк під перевірку**:
  жовті комірки (ставка, години, лікарняні, коригування) редагуються руками,
  колонки Оплата / Нараховано / До виплати — **формули**, тому будь-яка правка
  одразу перераховує підсумки. Коефіцієнти винесені в окремі комірки B5–B7.

## Зарплата

```
базова     = звичайні_години × ставка
додаткові  = додаткові_години × ставка × EXTRA_SHIFT_MULTIPLIER (1.5)
лікарняні  = дні × SHIFT_NORM_HOURS × ставка × SICK_PAY_RATE (0.7)
```
Все налаштовується в `.env`.
